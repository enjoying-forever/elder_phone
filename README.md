# 看图电话（Android）

面向不识字或识字较少老人的原生 Android 电话应用。保留原来的界面结构与操作，不增加确认窗口。

## 操作方式（保持原版）

- 默认打开「拨号」：上方最近通话，下方数字键盘。清除键一次清空号码，绿色拨打键直接播报后拨号。输入号码时，上方会同步筛选匹配过的通话记录。
- 「通讯录」：点一下联系人选中并听名字，再点同一项拨号；也可用原来的上下箭头选择，再按「拨打电话」。
- 保留「回到顶部」、联系人照片、原来的列表操作方式。
- 不使用照片分页、不增加拨号确认框或管理码窗口。拨号页底部有一个框，可隐藏或重新显示数字键盘。

## 适老细节

- **防手抖误拨**：选中一项后 0.7 秒内再点同一项不会拨号（手抖连点只算选中并听名字），停一下再点才拨打。
- **听号码**：点一下号码框，按“幺三八，零零幺三，八零零幺”分组读出整串号码，拨打前可核对。陌生号码播报和“正在拨打”也按同样分组读。
- **按键震动**：数字键、列表、标签和通讯录按钮点击时短震一下，听力不好也能确认按到了。跟随系统“触摸振动”设置。
- **不自动锁屏**：应用在前台时，每次触摸后 2 分钟内保持亮屏，慢慢输号码不会中途黑屏；离开应用立即恢复系统设置。
- **常用联系人置顶**：在系统通讯录里给常打的家人点“收藏/星标”，通讯录页会排在最前面，“回到顶部”直接到这些人。
- **系统大字体**：界面本身已是大字，系统字体放大最多按 1.3 倍生效，避免老人把系统字体调到最大后按钮文字被截断。

## 统一视觉样式

- 采用蓝白配色，顶部只有电话听筒和联系人图案；点击分别播报“拨号”“通讯录”。
- 数字键盘采用 8dp 小圆角矩形，按键间隔更紧、数字更大。拨号页上方通话记录更大，可显示多行；键盘可隐藏后浏览更多记录。通讯录约 65% 留给联系人列表。
- 两页统一蓝白风格，顶部图案、头像和列表选中均使用蓝色；只有实际拨打按钮使用绿色。通话记录显示 `yyyy-MM-dd HH:mm`，仅“未接电话”状态文字标红，选中后也保持红字。
- 仅首次点击未接记录时播报相对日期和时间，例如“昨天，上午十点三十分，未接电话，女儿”；普通记录仍只读名字，再点同一项回拨。
- 小屏数字按键按可用高度缩放文字，避免数字上下裁切；双行操作按钮增加行距。
- 视觉常量集中在 `KantuTheme.kt`，仅调整样式，不改变点击、播报、拨号和隐藏设置逻辑。

## 家人设置

- 顶部不再显示齿轮。**长按顶部电话或联系人图案 3 秒**，直接打开原来的播报音量设置。
- 设置离开应用或打开 60 秒后自动关闭。没有密码或多级菜单。
- 普通播报强度独立保存，范围 30%～100%。拨号前播报使用 100% 应用内强度，不改系统音量。
- 实际响度仍受系统媒体/无障碍音量、静音、耳机及中文 TTS 引擎影响，不能保证系统静音时大声。
- 接通后的音量和免提仍由系统电话控制。
- 请在系统通讯录配置真实照片和老人熟悉的称呼，并给最常打的家人加星标（收藏）。通话记录权限可选，不影响通讯录和键盘拨号。

## 保留的底层修复

- 旧语音回调、语音失败和离开应用不能触发延迟拨号。切换标签取消尚未完成的拨号播报。
- 同一联系人有多个号码时分别选择，不再因联系人 ID 相同而误拨另一个号码。
- 不注入演示号码，演示标记禁止拨打。过滤 USSD/任意 URI 和异常号码。
- 读取权限/数据异常容错；最近号码去重，最多 40 个；照片按需缩小，避免原图内存过大。
- 保留 `VoiceAnnouncer`、`CallGateway`、`ContactDirectory` 扩展接口，目前仍只做语音播报打电话。

## 构建和验证

需要 JDK 17、Android SDK Platform 35、Build Tools 35.x，配置 `JAVA_HOME` 和 `ANDROID_HOME`，或在不入库的 `local.properties` 设置 SDK 路径。

```powershell
.\gradlew.bat :app:assembleDebug :app:lintDebug :app:testDebugUnitTest
.\gradlew.bat :app:connectedDebugAndroidTest
```

APK：`app/build/outputs/apk/debug/app-debug.apk`。

界面测试使用假联系人、假语音和假拨号，不会拨打真实电话。测试覆盖原版列表/键盘操作、号码筛选通话记录、隐藏键盘、未接电话播报、同人多号码、切页取消播报、隐藏设置、演示安全、防手抖连点和点号码框分组读号。真机仍需检查中文声音、静音/耳机、双 SIM、飞行模式和真实通话。

项目沿用原安装签名。仓库内已有签名密钥及密码，不应作为保密的生产签名；正式发行前需要单独规划签名管理，不要直接替换密钥造成老版本无法覆盖安装。
